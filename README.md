# 文件自动脱敏工具（MVP）

法律文书脱敏：合同、函件 Word/PDF，证据卷宗扫描件（自动 OCR）。纯本地运行，文件不出本机。

## 安装（首次）

```bash
cd 文件脱敏工具
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
```

## 用法

```bash
# 给 AI 分析：占位符 + 映射表，可反解
.venv/bin/python 脱敏.py 待脱敏/ --mode ai

# 对外提交：掩码，不可逆，不生成映射表
.venv/bin/python 脱敏.py 待脱敏/ --mode external

# 单个文件
.venv/bin/python 脱敏.py 合同.docx --mode ai

# 反解（仅 AI 模式，需映射表）
.venv/bin/python 脱敏.py --restore 脱敏_合同.映射表.json 脱敏_合同.docx
```

## 两种模式

| | AI 分析模式（--mode ai） | 对外提交模式（--mode external） |
|---|---|---|
| 人名 | `<PERSON_1>` | 张* |
| 机构 | `<ORG_1>` | 某甲公司、某乙公司（甲乙丙丁顺延） |
| 身份证 | `<IDCARD_1>` | 330203********1234 |
| 手机号 | `<PHONE_1>` | 138****5678 |
| 银行卡 | `<BANKCARD_1>` | ************1234 |
| 邮箱 | `<EMAIL_1>` | a***@domain.com |
| 统一社会信用代码 | `<USCC_1>` | 913302********12X3 |
| 地址 | `<ADDR_1>` | 浙江省宁波市**** |
| 映射表 | 生成 `.映射表.json`，可反解 | 不生成，不可逆 |

同一实体全文替换结果一致（张三出现 37 次都是 `<PERSON_1>`），文档可读性不受影响。

## 识别能力与边界（重要）

**自动识别（正则 + 校验算法）**：身份证（18 位含校验位验证、15 位老证）、手机号、座机、银行卡（Luhn 校验）、邮箱、统一社会信用代码。

**实体清单识别**：[实体清单.txt](实体清单.txt) 中手工维护的人名、机构、地址，全文一致替换。第一版不上 NER 模型，**清单外的姓名抓不到**——靠两个补偿机制：

1. **疑似待确认实体报告**：脚本自动扫描“原告/被告/甲方/乙方/××律师”等标签后的文字，列出来供你确认，确认后补进实体清单，下次运行即自动脱敏
2. **未脱敏长数字串报告**：10 位以上未被脱敏的数字串（可能是账号、编号）列出供人工确认

**运行后必须人工通读一遍脱敏件再外发——脚本降低漏抓率，不保证零漏抓。**

## 其他边界

- 老版 `.doc` 不支持，先另存为 `.docx`
- PDF（含扫描件）输出为脱敏版 `.txt`，不保留原版式；docx 输出保留正文段落，**表格内容扁平化为段落**追加在文末
- 扫描件 OCR 依赖 `rapidocr-onnxruntime`（纯离线本地识别）；未安装时扫描件自动跳过并提示，不影响同批其他文件
- 批处理时单个文件失败不中止整批，跳过并提示
- **映射表 `.映射表.json` 的保密级别与原文件相同，严禁随脱敏件一起外发**；对外提交模式根本不生成映射表
- 身份证校验位算法、Luhn 算法为通用公开算法；校验不过但形状像身份证/银行卡的长数字串仍会脱敏（宁可多脱敏，类型标签可能显示为兜底类型）
- 案号、车牌号等暂不自动识别，确需脱敏的可手工加入实体清单

## 已实测（2026-08-30，虚构数据样例）

- docx 正文 + 表格：9 类实体（人名/机构/身份证/手机/座机/邮箱/银行账号/信用代码/地址）全部识别，跨段落同实体占位符一致
- 中文 PDF 文本层：识别与输出正常
- AI 模式反解：还原后与原文逐字一致
- 对外模式：掩码格式符合常规惯例，无映射表产出
- 扫描件 OCR 路径：已实测（2026-08-30，`rapidocr-onnxruntime 1.4.4`，扫描卷宗 PDF 识出人名/身份证/手机号并正确脱敏）。注意：该包要求 Python < 3.13，只能装在 `.venv`（3.9），`.venv13` 装不了
